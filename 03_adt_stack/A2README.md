## Reflection questions
- QUESTION 1: What value does topIndex hold immediately after construction, and why does that specific value make isEmpty() return the right answer with no special-casing?
- ANSWER 1: The value that the topIndex variable holds immediately after construction is -1. That specific value makes isEmpty() return the right answer because whenever any of the other methods are called (especially push), it changes topIndex. This means that whenever push is called on an empty list, topIndex becomes 0, the first valid index number in an array. Pop decrements topIndex, meaning that topIndex, after the value of index 0 is removed, is back to -1. Basically, -1 isn't a valid index and the push and pop functions work in a way so that the index isn't -1 when there is something in the stack, and it is -1 when there isn't anything in the stack.
- QUESTION 2: Walk through push step by step, in words: what happens to data and topIndex, in what order, and why would swapping that order break the stack?
- ANSWER 2: First, the topIndex variable is checked to see if it is less than 99 (first index is 0 so 100th item in the stack is index 99 in the array). If it is, it increases the topIndex by 1(starts at -1 so if an item is being added to an empty list, it becomes 0) and sets that index equal to the int "value" parameter passed. If topIndex isn't less than 99, it prints an "error message" (just says that the user can't push to a full stack ) and also prints a -1 (push doesn't return anything, that is solely for consistency with the rest of the code). Swapping the order would break the stack as, for the first item being pushed into the stack, it would try to do data[-1] = value. -1 isn't a valid index.
- QUESTION 3: Give the time complexity of push, pop, peek, isEmpty, isFull, and size, individually, in Big-O. For each one, justify it by describing what your code actually does, not by naming the general rule for stacks.
- ANSWER 3: The time complexity of push is O(1), as it's just a conditional, arithmetic, assignment, and a couple of print statements if the conditional is false. The time complexity of pop is also O(1) as it uses a conditional that, if true, has assignment, decrementation, and returning. If it's false, it just prints out an "error message". The peek function is also O(1) as it is a conditional that either returns a value and might print an "error message" if the condition is false. isEmpty is also O(1) as that is just a conditional with an else statement. Same goes for isFull, so it is O(1). Finally, the size function just returns topIndex + 1, which is O(1), so the whole function runs in O(1). 
- QUESTION 4: Exactly what happens in your code when push is called while the stack is full? State what prints (if anything), what gets returned (if anything), and whether topIndex changes. Then say why you chose that behavior.
- ANSWER 4: When push is called when the stack is full, topIndex does not change. Instead, it prints out a message that says that the user can't push to a full stack. Then, it prints out a -1. That -1 isn't necessary in this case as push doesn't return anything, but I deliberately added that decision to make it consistent with pop and peek, which return a -1. The function returns -1 as that is a sentinel value that can't be used in the C++ array.
- QUESTION 5: Exactly what happens when pop or peek is called while the stack is empty? Same level of detail as above.
- ANSWER 5: When pop or peek are called while the stack is empty, both print out a message that basically says "Stack is empty, can't pop/peek" (depending on the function being used). Then it returns a -1 as those two functions have to return something. As explained in the push explanation, it returns -1 because that is a sentinel value.
- QUESTION 6: Your array is fixed at 100 slots. If a caller needed more room than that, what would have to change in your class to support it, and what would it likely cost in terms of the time complexity you gave in question 3?
- ANSWER 6: If a caller needed more room than that, I would need to alter the code so that the array's size changes. If it can be done like in java (data = new int[10]), then I would do that. But if it can't, I would probably need to use the STL (assuming it has something similar). If the STL doesn't have something similar, I would ask the user before even making the array what size stack they want, then making the array with that answer.
- QUESTION 7: Without looking anything up: if this stack were built on a linked list instead of an array, name one advantage and one disadvantage that trade-off would bring, based on what you already know about how arrays and pointers behave differently.
- ANSWER 7: Without looking anything up, the advantage of building the stack on a linked list is that they don't have a set length, unlike an array. This solves the issue in question 6. The disadvantage would be time complexity. In an array, you already set the number of values the array can hold, so changing that value is O(1) as it is just assignment. In a linked list, either the new value is the header, so everything else would need to be pushed back (that's O(n)), or the data is appended to the end, which is also O(n).
